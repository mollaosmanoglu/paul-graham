### Language Design

<Note kind="essay" source="Hackers and Painters" href="http://www.paulgraham.com/hp.html" date="2003-05">
A programming language is for thinking of programs, not for expressing programs you've already thought of.
</Note>

<Note kind="essay" source="The Python Paradox" href="http://www.paulgraham.com/pypar.html" date="2004-08">
Real ugliness is not harsh-looking syntax, but having to build programs out of the wrong concepts.
</Note>

### Abstraction

<Note kind="essay" source="Why Arc Isn't Especially Object-Oriented" href="http://www.paulgraham.com/noop.html">
You should be able to define new types, but you shouldn't have to express every program as the definition of new types.
</Note>

### Choice

<Note kind="essay" source="Weird Languages" href="http://www.paulgraham.com/weird.html" date="2021-08">
So if you want to expand your concept of what programming can be, one way to do it is by learning weird languages.
</Note>
